# CLI exception ingestion

The Atmos consumer contract is part of `pacts/atmos-AtmosPro.json`, generated by
`TestPact_Exceptions` in `pkg/pro/consumer_exceptions_pact_test.go`. It exercises
the production `ExceptionTransport`, including the Sentry SDK envelope serializer,
with deterministic test credentials and a fixed event timestamp. No live OIDC
requests are made by these interactions.

## Interactions

| Provider state | Request | Response |
| --- | --- | --- |
| `repository 123 accepts exception envelopes` | `POST /api/v1/events/123/exceptions`, token `pact-accepted-oidc-token` | 200 |
| `repository 123 rejects exception authentication` | Same endpoint, token `pact-rejected-oidc-token` | 401 |

Both requests use `Content-Type: application/x-sentry-envelope` and
`X-Sentry-Auth: Sentry sentry_version=7, sentry_client=atmos-cli/test, sentry_key=<token>`.
The client version varies in production. Pact's V2 header matching splits comma
separated fields; the fixed test version lets the contract check all three fields
exactly without weakening the authentication matcher.

The envelope fixture `pkg/pro/testdata/exception.envelope` specifies event ID,
fingerprint, execution ID, stack/component identity, and unprefixed tags
`team: "platform"` and `production: "true"`. Request bytes are checked against this
fixture independently of production serialization. A response body is not consumed
and is deliberately unconstrained.

## Provider acceptance criteria (Atmos Pro)

Tracked in [issue #3219](https://github.com/cloudposse/atmos/issues/3219).

These require implementation in the Pro backend; they cannot be verified by this
CLI checkout or by a successful mock-server response alone:

1. Verify the committed Atmos Pact against Pro's real exception route. Provider
   state setup should stub the OIDC verifier or use locally signed test credentials
   for the two fixed tokens. The accepted state authorizes repository `123`; the
   rejected state denies authentication. Never use production credentials.
2. Add a provider integration test through the real route, decoder, ingestion
   service, and test storage. Submit the accepted envelope, load the persisted
   exception by event ID, and assert `team == "platform"`, `production == "true"`
   (a string), unchanged fingerprint, and the same execution ID.
3. Assert there are no `atmos.label.team` or `atmos.tag.production` rewrites, and
   verify that the rejected interaction persists no exception.
4. If ingestion is asynchronous, drain the test queue before querying storage.
   Use an isolated test repository and clean up its persisted events after the test.

Pact checks request/response compatibility. The storage assertion is a separate
acceptance requirement because Pact cannot detect silently dropped tags.

## Local validation

Run the complete suite so existing interactions remain covered:

```sh
go run github.com/pact-foundation/pact-go/v2 install --libDir /absolute/path/to/pact/lib
CGO_LDFLAGS="-L/absolute/path/to/pact/lib" \
  LD_LIBRARY_PATH=/absolute/path/to/pact/lib \
  go test -tags pact ./pkg/pro/... -run TestPact -count=1
```

Use an absolute library directory on macOS as well. The installer uses the
pact-go version pinned in `go.mod`. CI runs this command in the main test workflow
and checks that the committed contract is current. Local unit tests separately
cover token refresh, masking, opt-outs, duplicate suppression, bounded shutdown,
and exit-code preservation.
