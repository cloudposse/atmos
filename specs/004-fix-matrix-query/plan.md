# Implementation Plan: `--filter` for `describe affected` and No Silent `--query` with Matrix Output

**Branch**: `1200-fix-matrix-query` | **Date**: 2026-10-30 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/004-fix-matrix-query/spec.md`

## Summary

`atmos describe affected --format=matrix --query ...` ignores the query because `describeAffectedExec.view()` handles the matrix format before it reaches the query branch (`internal/exec/describe_affected.go:761-771`). The spec resolves this by:

1. Adding a `--filter` flag, a YQ predicate evaluated per affected item and per dependent. It applies to every output format, keeps item shapes intact, and prunes a failing item together with its whole dependents subtree.
2. Making `--query` with `--format=matrix` fail with a hint that points to `--filter`.

Technical approach: reuse the predicate semantics already shipped for `list instances --filter` (`pkg/list/filter.YQPredicateFilter`), add a small per-item `Matches` method to it, wire the flag through the existing `describe affected` selector flag parser (`ATMOS_DESCRIBE_AFFECTED_FILTER`), and apply the predicate in the shared dependents-finalizing path before flattening. Upload and `--query` guards follow the existing `resolveAffectedSelectors` pattern.

## Technical Context

**Language/Version**: Go 1.26 (per `go.mod`)

**Primary Dependencies**: cobra and viper through `pkg/flags` (`flags.NewStandardParser`), `pkg/list/filter` (YQ predicate), `pkg/utils.EvaluateYqExpression`, `pkg/matrix`, the error builder in `errors/`

**Storage**: N/A

**Testing**: `go test` with table-driven unit tests. Mocks are generated by `mockgen` where an interface is needed, and `cmd.NewTestKit(t)` is used for cmd tests. The existing fakes in `internal/exec/describe_affected_*_test.go` are reused.

**Target Platform**: Linux, macOS and Windows CLI

**Project Type**: CLI (single Go module)

**Performance Goals**: no measurable regression for runs without `--filter`. With `--filter`, one YQ evaluation per item and per dependent, which is the same order as `--query` today.

**Constraints**:
- Files stay under 600 lines. `describe_affected.go` is already over that, so new code goes into new files.
- `viper.BindEnv`/`BindPFlag` are forbidden outside `pkg/flags/`.
- Matrix output without the new flags stays byte-identical.

**Scale/Scope**: the affected set is typically tens to low thousands of items, so the filter cost is negligible next to computing the affected set.
