# Fix: Keep registry-cache init fingerprints stable across proxy restarts

**Date:** 2026-10-28

## Summary

A new ephemeral Atmos registry-proxy port no longer invalidates a successful init marker. Each invocation still starts a live proxy and passes its current endpoint to Terraform/OpenTofu.

## Context

The generated Terraform RC file changed on every registry-enabled invocation because the proxy listens on an available loopback port. Hashing those generated bytes caused redundant init calls on both main and the reconciled component-provider extraction, despite unchanged component dependencies.

## Changes

The cache contributes a separate semantic representation containing the same provider/module installation rules and a symbolic Atmos-owned endpoint. The identity includes the cache root, TLS certificate, metadata policy, registry hosts, and effective user RC configuration.

Generated RC files have explicit, process-local provenance. A concurrency-safe registry binds each temporary path and exact generated-content digest to its semantic identity; pipeline cleanup removes the registration and file. Modified generated content falls back to its actual bytes. User-managed files and user-specified localhost endpoints retain exact content identity and existing override precedence. No URL pattern is stripped from arbitrary user configuration.

Root configuration, provider locks, backend configuration, init variables and ordinary environment fingerprint inputs remain in the fingerprint. This is a bug fix with no configuration or edition migration. Existing markers can require one initialization when moving to the corrected identity format.

## Validation

A regression using two simultaneously running real local proxy listeners failed before the fix and now proves different live RC bytes yield the same semantic fingerprint. Unit tests cover user endpoint/cache-root/policy/credential changes, generated-file edits, cleanup, concurrency, and user RC precedence. Autoinit, RC, and cache suites passed; the full Terraform component short suite passed. Race tests passed for autoinit and RC.

Real Linux Terraform 1.15.6 and OpenTofu 1.12.5 passed all four plugin/registry-cache combinations: cold init followed by warm plan, a fresh process, apply, and JSON output. Registry modules also initialize once and skip warm init. Explicit user RC file localhost changes and lockfile edits still trigger init. Registry-enabled variable-dependent local modules select and apply v1 then v2 with the expected fingerprint/init change; warm runs and pass-vars opt-out/restore remain correct. Unsupported Terraform nonconst sources remain rejected while its const-variable counterpart passes. Network-disabled containers verified warm registry modules, manifest-retained module recovery, and filesystem-mirror provider reinstallation. Provider-constraint/backend changes and same-path explicit user RC edits retain the expected init/reconfigure behavior. Parallel fleet execution still suppresses the unsafe shared plugin cache and skips warm init. Scoped provider/module inspection, deletion, pruning, dry runs, and TLS-file exclusion passed. Native macOS retained its expected untrusted-cache refusal without engine startup.

## Follow-ups

The broader field-findings repair plan tracks final combined acceptance and repository-wide validation. Native macOS registry TLS continues to require the existing OS trust mechanism; this repair does not install certificates or bypass verification.
