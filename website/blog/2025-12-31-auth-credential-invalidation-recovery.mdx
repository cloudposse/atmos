Access keys get rotated. Sometimes you rotate them, sometimes a policy or a security team does it for you, and either way the tools holding the old keys rarely say so. They fail with an error about a token, which sends you looking for an expired session instead of the keys underneath it. Atmos now recognizes that error for what it is, throws out the dead credentials, and asks you for the new ones on the spot.

<!--truncate-->

## The Problem

If your AWS access keys were rotated or revoked on the AWS side, the sequence looked like this:

1. Your session token would expire (normal)
2. `atmos auth login` would fail with a cryptic error
3. `atmos auth logout` + `atmos auth login` wouldn't fix it
4. Only full user reconfiguration would work

The obvious remedies did nothing, because nothing was wrong with the session — the stored access keys behind it were dead, and Atmos kept trying to use them. Work stopped until someone figured out that the fix was to reconfigure the identity from scratch.

## The Fix

When AWS STS answers `atmos auth login` with `InvalidClientTokenId`, Atmos now clears the stale credentials out of the keyring, prompts you for replacements inline, and retries authentication with what you enter. If you cancel the prompt, the error tells you what was being asked for and how to supply it.

```shell
$ atmos auth login dev-admin

⚠ AWS credentials are required for identity: dev-admin

AWS Access Key ID: AKIAXXXXXXXXXX
AWS Secret Access Key: ********
MFA ARN (optional): arn:aws:iam::123456789012:mfa/user
Session Duration (optional, default: 12h): 36h

✓ Credentials saved to keyring: dev-admin

Enter MFA Token: 123456

✓ Authentication successful!

  Provider   aws-user
  Identity   dev-admin
  Account    123456789012
  Region     us-east-1
  Expires    2024-12-24 04:58:00 MST (35h 59m)
```

There is no separate `atmos auth user configure` step. Recovery happens in the command you already ran.

## Session Duration

The session duration you set during `atmos auth user configure` was not being passed through to the call that generates the session token. If you configured 36 hours with MFA, your token still expired after 12 hours, the default. Long MFA sessions now last as long as you configured them.

## Error Detection

Atmos now recognizes three AWS STS errors for IAM User authentication and reacts to each one differently:

| Error                   | Meaning                 | Automatic Action                               |
|-------------------------|-------------------------|------------------------------------------------|
| `InvalidClientTokenId`  | Keys rotated/revoked    | Clears stale credentials, prompts for new ones |
| `ExpiredTokenException` | Session expired         | Guides to re-login                             |
| `AccessDenied`          | Missing IAM permissions | Guides to check IAM policies                   |

## Applies To

All of this covers **AWS IAM User** identities (`aws/user` kind). AWS SSO, assume-role, and permission-set identities use different authentication flows and are unaffected.

## How to Use It

Nothing to configure. Run `atmos auth login` as usual, and answer the prompt if one appears.

To check where an identity stands, `atmos auth whoami` reports the session token's expiration, and warns you with the command that fixes it when the credentials are expired or invalid:

```shell
$ atmos auth whoami dev-admin
✗ Current Authentication Status

  Provider      aws-user
  Identity      dev-admin
  Expires       2025-12-30 10:11:05 EST (expired)
  Last Updated  2025-12-30 09:55:34 EST

⚠ Credentials may be expired or invalid.
  Run 'atmos auth login --identity dev-admin' to refresh.
```

A subprocess under `atmos auth exec` that dies on expired credentials gets the same treatment, so the refresh command is right there next to the failure:

```shell
$ atmos auth exec --identity dev-admin -- aws sts get-caller-identity
An error occurred (ExpiredToken) when calling the GetCallerIdentity operation: The security token included in the request is expired

  Tip  If credentials are expired, refresh with:
      atmos auth login --identity dev-admin
```
