Shared authentication configuration can leave account and role values for stacks to supply. Validating only the global configuration rejects those incomplete definitions before their component overrides are considered. The [auth validation command](/cli/commands/auth/validate) can now check the merged configuration for a selected stack or component.

## The Problem

A global identity can provide the shared settings while a stack or component supplies its principal. Global validation alone cannot determine whether that final configuration is valid.

## The Fix

Select a stack to validate every concrete component's merged authentication configuration independently. Add a component selector to narrow the check. Errors identify the stack, component type, and component involved.

Unscoped validation remains strict. Validation checks configuration without authenticating or executing dynamic stack expressions; required values that remain dynamic are reported as not fully validated.

## How to Use It

```shell
atmos auth validate --stack dev
atmos auth validate --stack dev --component app
atmos auth validate
```

The component selector requires a stack. See the [command reference](/cli/commands/auth/validate) for selection and validation details.
