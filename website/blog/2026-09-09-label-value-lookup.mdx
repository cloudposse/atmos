A runner selector or cost center belongs on the component that uses it, but passing just that
value into a module or workflow has required a Go template. The [`!labels` function](/functions/yaml/labels)
now accepts a key and an optional fallback, making individual labels as easy to read as the full map.

<!--truncate-->

## The Problem

The existing template `{{ .metadata.labels.runner }}` reads one label, while bare
[`!labels`](/functions/yaml/labels) returns all of them. A shared workflow mixin also needs to handle components
that have no runner label, without duplicating the same value across every stack.

## The Fix

Use [`!labels key [default]`](/functions/yaml/labels#single-label-lookup) to retrieve a string
from the component’s resolved [metadata labels](/stacks/components/component-metadata#labels).
An absent key uses the explicit default or produces an error if none was supplied.
Existing empty-string values are preserved. Bare `!labels` continues to return the full map.

## How to Use It

```yaml
components:
  terraform:
    cluster:
      metadata:
        labels:
          cost-center: platform
          runner: self-hosted-large
      vars:
        cost_center: !labels cost-center
        owner: !labels owner "Platform Team"
      settings:
        pro:
          pull_request:
            synchronize:
              workflows:
                atmos-terraform-plan.yaml:
                  inputs:
                    component: "{{ .atmos_component }}"
                    stack: "{{ .atmos_stack }}"
                    runner: !labels runner ubuntu-latest
```

Keys are literal, including dots, slashes, and hyphens. Quote fallback values containing spaces;
use `""` when the fallback should be an empty string. Values reflect
[stack defaults and component inheritance](/stacks/components/component-metadata#global-stack-wide-metadata).

For the GitHub runner input and apply-routing requirements, see
[choosing a runner per component or stack](/cli/configuration/settings/pro#choose-a-runner-per-component-or-stack).
