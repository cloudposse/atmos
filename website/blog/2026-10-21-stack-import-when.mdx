A stack's native labels can now select the configuration it inherits. Set `metadata.labels.pci: true` and use
`when: !cel labels.pci == true` to include a PCI mixin. Stacks with `pci: false` keep their shared defaults, so the same
import list supports both behaviors with a checked-in label that stays consistent locally and in CI.

## The Problem

A [mixin](/howto/mixins) groups configuration that a stack can reuse. Previously, every entry in a stack manifest's
[`import`](/stacks/imports) list was always processed. To try an optional mixin, you had to change the import list or
maintain a separate stack variant. There was no import-level condition to connect that choice to native stack labels.

## The Fix

An object-form stack import now accepts the same [`when` condition](/stacks/imports#conditional-imports) as the config
imports in `atmos.yaml`. When the condition does not match, Atmos never reads the file, so a skipped import cannot fail
and adds nothing to the stack.

A condition is one of these:

- `ci` imports the file only when Atmos detects a CI environment.
- `local` imports it only when Atmos does not.
- `always` and `never` import it unconditionally or not at all.
- `!cel <expression>` evaluates a [CEL expression](/steps#conditional-execution) that can read the process environment
  through `env` or native stack labels through `labels`, for example `!cel labels.pci == true`.

A list of conditions requires all of them to hold. A condition that cannot be evaluated, such as an expression over an
environment variable that is not set, does not match, and the reason is written to the debug log.

## How to Use It

Set a native Atmos label on the stack and use it to select a mixin:

```yaml title="stacks/payments.yaml"
name: payments

metadata:
  labels:
    pci: true

import:
  - catalog/app
  - path: mixins/pci
    when: !cel labels.pci == true
```

The shared catalog sets `audit_logging_enabled: false`. The mixin turns it on:

```yaml title="stacks/mixins/pci.yaml"
components:
  terraform:
    app:
      vars:
        audit_logging_enabled: true
```

The `payments` stack includes the mixin because its `pci` label is `true`. A `standard` stack with `pci: false`
keeps the catalog default. This is an Atmos label, separate from Terraform variables and cloud resource tags.
Use an unquoted boolean: `true` and the string `"true"` are different values.

## Label Inheritance

Conditions see stack-wide `metadata.labels` from earlier imports, overlaid with the current manifest's labels.
The current manifest's labels also flow into its nested imports, taking precedence over those imported defaults.
Later imports do not change decisions already made. Put shared label defaults before the mixins that use them.

Only literal string and boolean labels are available during import resolution. Component-specific labels, Go templates,
and YAML functions are unavailable at this stage. An unavailable value masks an inherited value with the same name.
A missing label makes `labels.pci == true` fail to evaluate and the import is skipped; use
`has(labels.pci) && labels.pci == true` to handle an optional label explicitly.

Keeping flags in stack metadata makes the desired behavior reproducible locally and in CI. Changing a label intentionally
changes the configuration; plan and apply the same revision. Environment-based conditions remain available for cases
that need process-specific facts.
