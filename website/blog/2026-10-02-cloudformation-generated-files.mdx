Sharing one CloudFormation component across stacks becomes unsafe when each stack writes its own template or policy into the component directory. Concurrent commands can overwrite the files another deployment is about to read. Atmos can now generate these files inside a separate workdir for each stack and component.

<!--truncate-->

## The Problem

Templates and policies often need values from stack configuration, inherited defaults, or other components. Maintaining separate copies is tedious, while generating them into a shared source directory risks mixing values between deployments.

## The Fix

CloudFormation components now support the same `generate:` filename-to-content format as other component types. With generation enabled, a nonempty block automatically uses an isolated workdir. Atmos resolves local or provisioned source files, generates the configured files, and reads the template and policy from that directory.

Generation errors stop the command before deployment. Dry-run and commands that only inspect or delete deployed stacks do not generate files or fetch sources. Workdir isolation separates distinct stack/component instances; it does not serialize simultaneous deployments to the same AWS stack.

## How to Use It

Enable generation in `atmos.yaml`:

```yaml
components:
  aws/cloudformation:
    auto_generate_files: true
```

Then declare a generated template in the stack manifest:

```yaml
components:
  aws/cloudformation:
    example:
      path: generated/template.yaml
      generate:
        generated/template.yaml:
          AWSTemplateFormatVersion: '2010-09-09'
          Resources:
            Value:
              Type: AWS::SSM::Parameter
              Properties:
                Type: String
                Value: '{{ .vars.value }}'
      vars:
        value: example
```

Use `path:` to select the generated template explicitly. Inline templates can also generate auxiliary files. Generation defaults to disabled, and explicitly disabling the workdir while generation is active returns an actionable error.
