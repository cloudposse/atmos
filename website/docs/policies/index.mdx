<Intro>
Use policies to regulate Atmos's execution lifecycle: control component operations and require
hooks at lifecycle events. For Terraform, use policies to inspect plan changes and reject operations
that violate your rules. Policies use CEL expressions or Starlark function bodies and load from `policy.d/` by default, with
`ATMOS_POLICY_DIR` available as an override. Use tag and label selectors to attach rules to instances.
</Intro>

<Experimental />

## Choose an input

| Input kind | Components | Evaluated when | Actions |
|---|---|---|---|
| `function` | Configuration loading and resolution | Before YAML function execution | `deny`, `require_approval` |
| `command` | All runnable CLI commands | Before argument validation and pre-run hooks | `deny`, `require_approval` |
| `component.command` | Shared stack resolution | Before component templates/functions and tool execution | `deny`, `require_approval` |
| `terraform.plan` | Terraform / OpenTofu | After a successful saved plan and before saved-plan apply | `deny`, `require_approval` |
| `operation` | Terraform, Helmfile, Helm, Kubernetes | At the component's lifecycle hook events | `deny`, `hooks`, `require_approval` |
| `atmos.affected` | All supported inventory types | During explicit affected analysis, before filtering or scheduling | `deny`, `require_approval` |

[GitHub Actions context](/policies/ci) is available to all kinds. [Admission](/policies/admission), plan, and lifecycle rules run
regardless of `--affected`; affected rules run only when affected analysis is requested.
Component configuration validation uses the separate
[`settings.validation` configuration](/validation/opa).

## Quick start

Create a policy file:

```yaml title="policy.d/terraform.yaml"
apiVersion: atmos/v1
kind: Policy
metadata:
  name: safety
  description: Prevent accidental deletion or replacement of managed resources.
spec:
  policies:
    prevent-deletion:
      on: terraform.plan
      action: deny
      reason: Resources must not be deleted or replaced
      rule: >-
        has(input.resource_changes) && input.resource_changes.exists(r,
          r.mode == 'managed' && 'delete' in r.change.actions)
```

Run a plan from the directory containing `policy.d/`:

```shell
atmos terraform plan vpc -s dev
```

A matching rule blocks the command. A plan containing no managed-resource deletions passes this
rule. To apply a passing saved plan:

```shell
atmos terraform apply vpc -s dev --from-plan
```

For CI enforcement, load policies from a [protected source](/policies/configuration#enforcement),
not an unreviewed pull-request checkout.
