<Intro>
Upload files or directories to Amazon S3. The `aws/s3` step compares content and delivery headers to skip unchanged objects.
</Intro>

## Usage

```yaml
steps:
  - name: upload
    type: aws/s3
    source: dist/
    destination: s3://acme-artifacts/releases/v1/
    region: us-east-1
```

The bucket must already exist. A directory's contents are uploaded recursively,
with relative paths preserved under the destination prefix. Empty directories
do not create objects. Remote objects absent from the source are retained.

## Examples

### Package and Upload an Archive

```yaml
steps:
  - name: package
    type: archive
    source: src/
    destination: handler.zip
    mtime: epoch
  - name: upload
    type: aws/s3
    source: '{{ .steps.package.value }}'
    destination: s3://acme-artifacts/lambda/v1/handler.zip
    region: us-east-1
  - type: log
    content: 'Artifact: {{ .steps.upload.value }}'
```

The [`archive` step's timestamp settings](/steps/type/archive#reproducible-archives)
produce reproducible archives, allowing unchanged builds to skip the upload.

### Publish a Directory

```yaml
steps:
  - name: publish
    type: aws/s3
    source: public/
    destination: s3://acme-site/assets/
    region: us-east-1
    cache_control: public, max-age=3600
```

Each file's content type is detected separately. Changing `cache_control` or
`content_type` causes an upload even when the file contents are unchanged.

For component hooks, see the
[CloudFormation asset packaging example](/stacks/components/aws-cloudformation#asset-packaging-hooks).
The same step is available in custom commands and workflows.

## Settings

<dl>
  <dt>`action`</dt>
  <dd>`upload` is the default and only supported action.</dd>

  <dt>`source`</dt>
  <dd>Required local file or directory. Relative paths use the step's working directory. Symlinks and special files are rejected.</dd>

  <dt>`destination`</dt>
  <dd>
    Required `s3://bucket/key` or `s3://bucket/prefix/` URI. For a single file,
    a trailing slash appends the source filename. For a directory, the path is
    always a prefix. With no path, files go at the bucket root. Escape literal
    `?` and `#` in keys as `%3F` and `%23`.
  </dd>

  <dt>`region`</dt>
  <dd>AWS region. When omitted, uses the resolved AWS identity or AWS SDK region configuration.</dd>

  <dt>`content_type`</dt>
  <dd>Optional content type applied to every uploaded file. Defaults to detection by extension, then file contents.</dd>

  <dt>`cache_control`</dt>
  <dd>Optional S3 `Cache-Control` header. Omitting it removes a previously configured value on the next upload.</dd>
</dl>

All settings except `action` support Go templates. Common step fields such as
[`working_directory`](/steps/working-directory), [`retry`](/steps/retry), and
[`when`](/steps#conditional-execution) also apply.

## Authentication

Workflow and custom-command steps use the AWS credentials prepared by the
runner, including their configured [`identity`](/steps/identity). Lifecycle
hooks use the component's resolved AWS identity. A CloudFormation delivery
target's identity does not select credentials for artifact uploads.

Without an Atmos identity, standard AWS credentials apply. Step environment
values for AWS profiles, credential files, regions, and access keys are passed
to the SDK without modifying the process environment. Use
`AWS_ENDPOINT_URL_S3` for an S3-compatible test endpoint.

The caller needs [`s3:GetObject`](https://docs.aws.amazon.com/AmazonS3/latest/API/API_HeadObject.html)
to inspect objects and [`s3:PutObject`](https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutObject.html)
to upload.
S3 can return `403` for a missing object if the caller lacks `s3:ListBucket`;
grant that permission on the bucket so absence can be distinguished from denied
access. Access errors fail the step without attempting an upload.
Bucket encryption policies may require additional KMS permissions.

## Incremental Uploads

Atmos records a SHA-256 digest in the object's `atmos-sha256` metadata and
supplies an upload checksum. An object is skipped only when the digest, size,
content type, and cache-control header match. Existing objects without Atmos
metadata are uploaded once. Comparison uses object metadata, so it does not
download remote content or require a shared deployment manifest.

Uploads replace objects at matching keys. Unrelated metadata on replaced
objects is not preserved. Bucket versioning and encryption defaults apply.
A directory upload is not atomic: if one file fails, earlier uploads remain.
Retrying skips successfully uploaded files whose content still matches.

## Results

| Value | Meaning |
| --- | --- |
| `.steps.upload.value` | Object URI for one file; configured destination for zero or multiple files. |
| `.steps.upload.values` | All object URIs, including unchanged files. |
| `.steps.upload.metadata.bucket` | Destination bucket. |
| `.steps.upload.metadata.key` | Object key for one file; configured prefix otherwise. |
| `.steps.upload.metadata.uploaded` | Number of uploaded objects. |
| `.steps.upload.metadata.unchanged` | Number of objects skipped because they already match. |

## Limitations

Files must be no larger than 5 GiB; multipart uploads are not supported.
The step does not create buckets, delete remote objects, or rewrite template
references. For CloudFormation Lambda assets, use a new object key per release
and pass it as a template parameter so CloudFormation can detect the change.
Dry-run does not initialize an AWS client or upload objects.
