## Usage

```shell
atmos plugin remove <alias>
```

Removal deletes the package from `plugins.packages` in `atmos.yaml` and from the lock in one
transaction. It refuses to remove a package whose `auth` provider or identity kinds are still
referenced by `auth.providers` or `auth.identities`. Downloaded releases stay in the
shared cache for other projects and for rollback.

When the active configuration sets `plugins.packages.<alias>.path`, `remove` refuses and says so. That
path comes from configuration, not from a file `remove` created, so edit the profile or `atmos.yaml`
that sets it, or deactivate the profile. The error names the active profiles. See the
[plugin development tutorial](/tutorials/plugin-development).

## Arguments and flags

<dl>
  <dt><code>alias</code></dt>
  <dd>Local package alias. Remove auth references before removing a release.</dd>
</dl>

## Examples

```shell
atmos plugin remove corporate
```
