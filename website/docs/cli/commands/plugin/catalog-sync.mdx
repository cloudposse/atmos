## Usage

```shell
atmos plugin catalog sync <catalog> [--inventory plugins/releases.yaml] [--head HEAD] [--skip-missing] [--verify-public]
```

Atmos reads the committed package inventory and each package’s committed manifest to select
release names, versions, and OCI repositories. It verifies those releases in OCI, merges their
metadata into the current catalog, and publishes one catalog revision. Earlier versions and existing listing/yank metadata
are preserved. A missing catalog can be created; an immutable version cannot be replaced with a
different digest.

Serialize catalog writers externally. Acquire the lock before reading the latest accepted source
and running sync. Revision and digest rechecks reject already-stale updates, but OCI
publication is not atomic compare-and-swap and does not replace a workflow concurrency lock.

The inventory uses the same package declarations as [release planning](./release-plan.mdx),
but catalog sync does not require runner mappings, compute build matrices, inspect build history,
or check version bumps. It does not build or publish plugin packages. Package versions come from
`plugin.yaml` at the selected revision; catalog metadata is extracted from verified OCI artifacts.

## Arguments and flags

<dl>
  <dt><code>catalog</code></dt>
  <dd>A configured catalog alias or an explicit oci:// catalog reference.</dd>
  <dt><code>--inventory</code></dt>
  <dd>Repository-relative YAML package inventory. Defaults to plugins/releases.yaml.</dd>
  <dt><code>--head</code></dt>
  <dd>Committed Git revision containing the inventory and manifests. Defaults to HEAD.
  Uncommitted working-tree edits are ignored.</dd>
  <dt><code>--skip-missing</code></dt>
  <dd>Skip release references that return not found, allowing another accepted package to finish publishing.
  Authentication, integrity, and other failures still fail the operation.</dd>
  <dt><code>--verify-public</code></dt>
  <dd>Verify each selected release anonymously before listing it, then upload the catalog and verify its
  published digest and payloads anonymously. Disabled by default; does not change registry visibility.</dd>
</dl>

## Examples

Run inside the catalog writer's serialized job, after checking out current accepted source:

```shell
atmos plugin catalog sync cloudposse --inventory plugins/releases.yaml --skip-missing --verify-public
```

A catalog-only inventory can omit build inputs and runner mappings:

```yaml
packages:
  repo-tools:
    path: plugins/repo-tools
    repository: oci://ghcr.io/acme/repo-tools
```

The referenced `plugins/repo-tools/plugin.yaml` must be committed at the selected revision.

Publication and catalog reconciliation are independent operations. A catalog failure does not
remove a successfully published immutable release. Rerun reconciliation after resolving the failure.

With `--verify-public`, a release that fails anonymous verification prevents the catalog update;
`--skip-missing` does not suppress verification failures. If verification of the uploaded catalog
fails, the catalog remains published and the command reports an error.

GHCR creates a new catalog package private, independently of its plugins and source repository.
After the first upload, select **Package settings → Danger Zone → Change visibility → Public** for
that catalog, then rerun the same sync command. Reconciliation preserves existing versions and yank
metadata. See [Public packages on GHCR](publish.mdx#public-packages-on-ghcr) for setup details and
GitHub's API limitation.
