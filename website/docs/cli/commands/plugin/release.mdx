## Usage

```shell
atmos plugin release [directory] --to <repository> [--sign] [--verify-public]
atmos plugin release --inventory plugins/releases.yaml --check
atmos plugin release --inventory plugins/releases.yaml --sign --yes --verify-public --catalog cloudposse
```

Atmos validates the package, builds every declared platform with bounded concurrency, runs conformance and authored tests
on the current host, packs a temporary OCI layout, and publishes the immutable manifest version.
The temporary layout is removed on success and failure. Cross-built platforms receive static
validation. Tests execute on the current host; testing on additional native runners is optional.

Use this command for the normal source-to-release path. No platform matrix or parallel workflow
configuration is required. CI that separates build credentials from publication can prepare a layout
with `plugin build --all-platforms`, `plugin test`, and `plugin pack`, then pass it to `plugin publish`
in the protected release job.

## Arguments and flags

<dl>
  <dt><code>directory</code></dt>
  <dd>Plugin source directory. Defaults to the current directory.</dd>
  <dt><code>--to</code></dt>
  <dd>Destination OCI repository for a directory release, without a tag or digest. Required unless using --check or --inventory. The version comes from plugin.yaml.</dd>
  <dt><code>--inventory</code></dt>
  <dd>Repository-relative committed package inventory. Each package builds from its recorded source in an isolated temporary worktree. Cannot be combined with a positional directory or --to.</dd>
  <dt><code>--check</code></dt>
  <dd>Validate, build, test, and pack without publishing. Cannot be combined with signing, public verification, or catalog publication.</dd>
  <dt><code>--head</code></dt>
  <dd>Committed inventory revision. Defaults to HEAD.</dd>
  <dt><code>--base</code></dt>
  <dd>Revision for independent package version checks. When omitted in CI mode, Atmos uses its CI provider to resolve the comparison base.</dd>
  <dt><code>--catalog</code></dt>
  <dd>Catalog alias or reference to reconcile after inventory publication. Reads accepted inventory from the current default branch on origin. Serialize releases with a shared writer lock. When some packages fail, the catalog is still reconciled for the packages that released, and each failed package keeps its existing catalog entry. See <a href="#when-a-package-fails">When a package fails</a>.</dd>
  <dt><code>--fail-fast</code></dt>
  <dd>Stop at the first failing package in an inventory release instead of continuing with the remaining packages. Nothing is reconciled or reported after the failure. Requires --inventory. Also ATMOS_PLUGIN_RELEASE_FAIL_FAST.</dd>
  <dt><code>--sign</code></dt>
  <dd>Sign the published multi-platform index using keyless Sigstore signing.</dd>
  <dt><code>--yes</code>, <code>-y</code></dt>
  <dd>Accept transparency-log publication without prompting. Requires --sign.</dd>
  <dt><code>--cosign-version</code></dt>
  <dd>Exact managed Cosign 3 version. Defaults to 3.1.3. Requires --sign when explicitly set.</dd>
  <dt><code>--verify-public</code></dt>
  <dd>After upload and any requested signing, verify anonymous access to the published digest and complete
  OCI graph. Disabled by default. Does not change registry visibility; a failed check leaves the upload intact.</dd>
  <dt><code>--source</code></dt>
  <dd>Repository URL recorded as the <code>org.opencontainers.image.source</code> annotation so registries such as GHCR link the package to its repository. Defaults to <code>metadata.repository</code> in <code>plugin.yaml</code>; pass <code>github-actions</code> to derive it from <code>GITHUB_SERVER_URL</code> and <code>GITHUB_REPOSITORY</code>. See <a href="/cli/commands/plugin/pack"><code>plugin pack</code></a>.</dd>
  <dt><code>--format</code></dt>
  <dd>Publication output format: table (default), json, yaml, csv, or tsv.</dd>
</dl>

## Examples

```shell
atmos plugin release ./my-plugin --to oci://ghcr.io/acme/my-plugin --sign --yes --verify-public
```

Signing and anonymous verification happen after publication. If either fails, the immutable release
remains published and the command fails. Retry with identical bytes; an existing version containing
different bytes is rejected. Inventory releases can reconcile a catalog with `--catalog` after the packages publish. [plugin catalog sync](catalog-sync.mdx) remains available separately.

A simple CI workflow needs two jobs: a read-only check job and a protected release job. Both run
`plugin release --inventory`; the release job rebuilds the recorded sources instead of transferring
artifacts. Hold a global release lock before starting the publishing command. Catalog reconciliation
fetches the current default branch after that lock is acquired, preserving newer accepted versions
even when an older queued workflow runs later.

For GHCR, the first upload creates a private package. With `--verify-public`, publication therefore
fails its anonymous access check until you select **Package settings → Danger Zone → Change visibility → Public**
in GitHub. Rerun the same release command afterward. The plugin and catalog are separate packages,
and each needs this one-time setting. Source repository labels do not make either package public.
See [Public packages on GHCR](publish.mdx#public-packages-on-ghcr) for the complete first-publication flow.

## When a package fails

An inventory release processes its packages in order, and one failing package does not block the
others. Atmos records the failure and continues with the remaining packages, so an unrelated
problem in one package, such as a signing or registry error, cannot hold back the releases after it.

When the run finishes:

- The packages that released are reported in the normal output, and with `--catalog` they are added
  to the catalog. A failed package keeps its existing catalog entry; the catalog never lists a version
  from a failed release.
- The command exits with an error that lists every failed package and how many packages did not
  complete, so CI still fails and the failures are visible in one place.
- If no package released, nothing is reconciled or reported.

Cancellation, for example Ctrl-C or a CI job being stopped, always ends the run: the current package
stops and no later package starts.

To stop at the first failure instead, as earlier Atmos versions did, pass `--fail-fast`:

```shell
atmos plugin release --inventory plugins/releases.yaml --sign --yes --catalog cloudposse --fail-fast
```

With `--fail-fast`, the packages after the failure are not started, and neither the catalog nor the
output is updated, even for packages that released before the failure.
