<Intro>
Display the current authentication context, including the effective identity and associated credentials. Useful for verifying which account is active and troubleshooting identity or session issues.
</Intro>

## Usage

```shell
atmos auth whoami [--identity <name>] [--output json]
```

## Examples

```shell
# Show current identity (human-friendly)
atmos auth whoami

# Interactively select identity to inspect
atmos auth whoami --identity

# Show a specific identity
atmos auth whoami --identity dev-admin

# Use short form of identity flag
atmos auth whoami -i dev-admin

# Interactive selection with short form
atmos auth whoami -i

# JSON output (redacts home directory from paths)
atmos auth whoami --output json
```

<dl>
  <dt>n/a</dt>

## Flags

<dl>
  <dt>`--identity` <em>(alias `-i`)</em></dt>
  <dd>
    Specify the target identity to inspect. This flag has three modes:

    - **With value** (`--identity admin`): Use the specified identity
    - **Without value** (`--identity`): Show interactive selector to choose identity
    - **Omitted**: Use the default identity configured in `atmos.yaml`, or prompt if no default is set

    **Environment variables:** `ATMOS_IDENTITY` or `IDENTITY` (checked in that order)
  </dd>

  <dt>`--output` <em>(alias `-o`)</em></dt>
  <dd>Output format. Supported: `json`. Default is human-readable.</dd>
</dl>

## Environment variables

<dl>
  <dt>`ATMOS_IDENTITY`</dt>
  <dd>Default identity when `--identity` is not provided.</dd>

  <dt>`ATMOS_AUTH_WHOAMI_OUTPUT`</dt>
  <dd>Set to `json` for JSON output by default.</dd>
</dl>

## Exit status

`atmos auth whoami` exits with `0` only when the identity has valid credentials. It exits with `1` when there are no credentials, or when the credentials are expired or invalid; the status is still printed (and, with `--output json`, the JSON document is still written to stdout) whenever the credential check completes. Use it in scripts to check whether you need to run `atmos auth login`.

Identities that do not get credentials through Atmos, such as the generic `ambient` kind and emulator identities, are the exception. The cloud SDK finds their credentials in the environment when a command runs, so there is nothing for Atmos to check. `whoami` exits with `0` for them, shows `Credentials: ambient, not managed by Atmos`, and adds `"ambient": true` to the JSON output.

For Azure identities, Atmos validates the credentials by reading the identity's subscription from Azure Resource Manager in the identity's cloud (public, US Government or China). When no subscription is set, or Resource Manager cannot be reached or does not confirm the subscription, the credentials are treated like AWS credentials when STS cannot be reached (see below). Only an expired token, or one that Resource Manager rejects, exits with `1`.

For AWS identities, Atmos validates the credentials with STS `GetCallerIdentity`. The call goes to the endpoint the identity authenticates against: `spec.endpoint_url` on the identity, or on its provider when the identity sets none (for example LocalStack or a private STS endpoint). Otherwise it goes to the public regional STS endpoint.

The command exits with `1` only when the answer is definite: the credentials have expired, or STS rejects them. When STS cannot be reached (offline, a blocked proxy, or a timeout), Atmos cannot check the credentials. In that case the result is based on their cached expiration time: unexpired credentials still exit with `0`, and a warning on stderr says that validation could not be performed. Once the credential check has completed, the JSON on stdout stays valid in every case. If there are no cached credentials and noninteractive authentication fails, the command returns an error before the status is reported, so no JSON document is written.
