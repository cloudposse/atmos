<Intro>
Set a value in your `atmos.yaml` configuration using a dot-notation path. The edit
preserves comments, anchors/aliases, Atmos YAML functions, and Go templates.
</Intro>

<CastPlayer title="atmos config set --help" src="/casts/screengrabs/atmos-config-set--help.cast" static chrome />

## Usage

```shell
atmos config set <path> <value> [--type <type>]
```

By default (`--type=auto`) the value's type is inferred in two steps: first from
the Atmos config schema when `<path>` matches a known field (`mcp.enabled` writes
a boolean, `settings.terminal.max_width` writes an int, and so on); otherwise from
the type of the value already at `<path>` (a `true`/`false` already there infers
bool, a bare number infers int/float). If neither source has an answer — most
commonly a free-form `vars` path being set for the first time — it falls back to
writing a string, and Atmos prints a warning when the value looks like it could
have been a bool or number, since that fallback is easy to miss. Pass `--type`
explicitly to skip inference entirely.

## Examples

```shell
# Type inferred from the schema -- writes a boolean, not the string "true".
atmos config set mcp.enabled true
atmos config set components.terraform.apply_auto_approve true

# Type inferred from the existing value at the path (no schema entry needed).
atmos config set vars.replicas 5

# String value (the fallback when neither the schema nor an existing value
# has an answer -- Atmos warns here since "true" looks non-string).
atmos config set vars.environment production

# Explicit --type overrides inference.
atmos config set --type=string logs.level Debug
atmos config set --type=int settings.terminal.max_width 120

# Raw YAML literal (lists, maps).
atmos config set --type=yaml 'logs.exclude' '["a", "b"]'

# Target a specific file.
atmos config set logs.level Trace --config ./atmos.yaml
```

## Arguments

<dl>
  <dt>`<path>` (required)</dt>
  <dd>Dot-notation path to the value (e.g. `logs.level`).</dd>
  <dt>`<value>` (required)</dt>
  <dd>The value to set. Interpreted according to `--type`.</dd>
</dl>

## Flags

<dl>
  <dt>`--type` (string, default: `auto`)</dt>
  <dd>How to interpret `<value>`: `auto` (infer from the schema, then from the existing value at the path, falling back to string), `string`, `int`, `bool`, `float`, `null`, or `yaml` (a raw YAML/yq literal inserted verbatim).</dd>
  <dt>`--config` (string, inherited)</dt>
  <dd>Target a specific `atmos.yaml` file instead of the one discovered in the current directory or git root.</dd>
</dl>

:::note
Edits that would alter or expand a YAML anchor or alias (including changing a value
shared by an anchor) are rejected to avoid silently mutating shared data, as are
multi-document YAML files and files that define the same anchor name more than once.
Comments, anchors, indentation width, and line endings (CRLF/LF) are preserved, but
blank lines between entries are dropped and non-indented sequence styles are
normalized when a file is edited.
:::
