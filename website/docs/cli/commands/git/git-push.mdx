<Intro>
Push commits from a repository configured under [`git.repositories`](/cli/configuration/git), or from any local path, to its remote. Atmos **never force-pushes**. When a push is rejected because the remote moved (another job or human pushed first), Atmos automatically retries: `pull --rebase`, then re-push, bounded by the shared `push.retry` policy (four total attempts by default).
</Intro>

## Usage

```shell
atmos git push <name-or-path> [flags] [-- <native git args>]
```

With a configured repository:

```yaml
git:
  repositories:
    flux-deploy:
      uri: https://github.com/acme/flux-deploy.git
      push:
        retries: 3        # bounded pull --rebase + re-push loop on rejection
```

```shell
atmos git push flux-deploy
```

## Examples

```shell
# Push a managed repository to its configured remote/branch
atmos git push flux-deploy

# Push a repository at a local path
atmos git push ./deployments

# Push a specific branch to a specific remote
atmos git push flux-deploy --remote=origin --branch=main

# Report what would be pushed without pushing
atmos git push flux-deploy --dry-run

# Pass native arguments to the underlying git push invocation
atmos git push flux-deploy -- --follow-tags
```

## Push Contention

A rejected non-fast-forward push is the most common failure mode in GitOps publishing — multiple components, CI jobs, or humans pushing to the same deployment branch. Atmos handles it instead of surfacing a raw Git error:

1. On rejection, including a concurrent remote ref update (`cannot lock ref ... is at ... but expected ...`), run `pull --rebase`, then re-push.
2. Wait with exponential backoff and random jitter, then retry according to `push.retry` (four total attempts by default; configurable per repository).
3. After exhaustion, fail with a clear error and hints (serialize publishers, or batch publishing).

Configure backoff and jitter using the shared [retry policy](/steps/retry) under `git.repositories.<name>.push`:

```yaml
push:
  retry:
    max_attempts: 4                  # initial attempt plus up to three retries
    backoff_strategy: exponential
    initial_delay: 250ms
    max_delay: 5s
    multiplier: 2
    random_jitter: 0.5
    max_elapsed_time: 30s
```

`max_attempts` includes the initial attempt. `max_elapsed_time` bounds the entire operation, including running Git commands. The delay cap applies before jitter. An explicit policy uses shared retry semantics without inheriting omitted fields from the defaults; `retry: {}` or `max_attempts: 1` makes one attempt. Legacy `push.retries` remains supported when `push.retry` is absent. Optional `conditions` narrow the rejected-push messages eligible for retry; they never enable retries for authentication failures or unrelated errors.

## Arguments

<dl>
    <dt>`name-or-path` <em>(required)</em></dt>
    <dd>
        A repository name configured under `git.repositories`, or a filesystem path to an existing Git working tree. URIs are not accepted — push operates on a local workdir.
    </dd>
</dl>

## Flags

<dl>
    <dt>`--branch` / `-b` <em>(optional)</em></dt>
    <dd>
        Branch to push. Defaults to the repository's configured branch, or the current branch.
        Environment variable: `ATMOS_GIT_BRANCH`
    </dd>

    <dt>`--remote` <em>(optional)</em></dt>
    <dd>
        Remote name. Default: `origin`.
        Environment variable: `ATMOS_GIT_REMOTE`
    </dd>

    <dt>`--dry-run` / `-n` <em>(optional)</em></dt>
    <dd>
        Report what would be pushed without pushing.
        Environment variable: `ATMOS_GIT_DRY_RUN`
    </dd>

    <dt>`--identity` <em>(optional)</em></dt>
    <dd>
        Atmos Auth identity to use for this operation (global flag). Overrides the repository's `auth.identity`.
        Environment variable: `ATMOS_IDENTITY`
    </dd>
</dl>

## Native Git Arguments

Arguments after `--` are passed verbatim to each underlying `git push` invocation (not to the `pull --rebase` recovery between retries).

```shell
atmos git push flux-deploy -- --follow-tags
```
