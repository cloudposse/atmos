<Intro>
  Fetch the deployed stack's template (`GetTemplate`) and write it to stdout.
  By default this is the fully-processed template CloudFormation actually
  deployed — the same shape a diff against the local render should compare
  against — not the user-submitted source.
</Intro>

<Experimental />

## Usage

```shell
atmos aws cloudformation get template <component> --stack <stack> [options]
```

```shell
atmos aws cloudformation get template vpc -s plat-ue2-dev
```

Fetch the original, user-submitted template instead of the processed one:

```shell
atmos aws cloudformation get template vpc -s plat-ue2-dev --original
```

By default the template is re-serialized as pretty-printed YAML, because CloudFormation often stores
the processed template as JSON. With `--original`, Atmos prints the body exactly as CloudFormation
returned it, byte for byte, with comments, quoting, and key order intact, so you can diff it against
your source file:

```shell
atmos aws cloudformation get template vpc -s plat-ue2-dev --original > deployed.yaml
diff template.yaml deployed.yaml
```

A stack that does not exist is an error that points at `atmos aws cloudformation apply`.

## Flags

<dl>
  <dt>`--stack`, `-s` <em>(required for a single component)</em></dt>
  <dd>Atmos stack. Required when operating on a single component; optional (and used only to narrow the selected set) with `--all`/`--affected`.</dd>

  <dt>`--original` <em>(optional)</em></dt>
  <dd>Fetch the user-submitted template instead of the processed one CloudFormation deployed, and print it exactly as returned, without re-serializing it.</dd>
