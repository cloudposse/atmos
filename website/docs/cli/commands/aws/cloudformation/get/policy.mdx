<Intro>
  Fetch the deployed stack's current stack policy (`GetStackPolicy`) and write
  it to stdout — the policy CloudFormation is actually enforcing, as opposed
  to the `stack_policy` configured on the component (which
  [`apply`](/cli/commands/aws/cloudformation/apply) installs before an update,
  or after a create).
</Intro>

<Experimental />

## Usage

```shell
atmos aws cloudformation get policy <component> --stack <stack> [options]
```

```shell
atmos aws cloudformation get policy vpc -s plat-ue2-dev
```

## Flags

<dl>
  <dt>`--stack`, `-s` <em>(required for a single component)</em></dt>
  <dd>Atmos stack. Required when operating on a single component; optional (and used only to narrow the selected set) with `--all`/`--affected`.</dd>

## Output

If the stack has no policy set (CloudFormation's default), `get policy` prints
a message saying so instead of an empty body.

If the stack does not exist, `get policy` fails with a stack-not-found error that points at
`atmos aws cloudformation apply`, instead of AWS's raw validation message.

:::note
`get policy` does not fire `before`/`after` hook events — only
[`apply`](/cli/commands/aws/cloudformation/apply),
[`diff`](/cli/commands/aws/cloudformation/diff),
[`delete`](/cli/commands/aws/cloudformation/delete),
[`drift detect`](/cli/commands/aws/cloudformation/drift/detect), and
[`drift describe`](/cli/commands/aws/cloudformation/drift/describe) do.
:::
