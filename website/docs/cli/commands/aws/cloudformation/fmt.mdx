## Usage

```shell
atmos aws cloudformation fmt <component> --stack <stack> [options]
```

## Examples

```shell
atmos aws cloudformation fmt vpc -s plat-ue2-dev
```

Check whether the template is formatted without writing changes (for CI):

```shell
atmos aws cloudformation fmt vpc -s plat-ue2-dev --check
```

Format all or affected components' templates in dependency order:

```shell
atmos aws cloudformation fmt --all -s plat-ue2-dev
atmos aws cloudformation fmt --affected --base origin/main --check
```

## Check mode

With `--check`, `fmt` reports each template and never writes:

- A template that is already formatted prints `already formatted`.
- An unformatted template prints `not formatted`; a single-component run then exits non-zero.
- With `--all`, `--affected`, `--tags`, or `--labels`, `fmt --check` checks every selected template and
  prints a line for each one, then exits non-zero once at the end, with an error that lists every
  unformatted template. It does not stop at the first one.

Components that point at the same template file share one check, identified by the file's resolved
path, so a shared template is reported once per run rather than once per component.

## Source Downloads

Formatting does not call CloudFormation. If the template comes from an uncached
remote source, Atmos downloads it first. Private sources may require authentication.
