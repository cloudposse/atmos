<Intro>
Use this command to vendor an `aws/cloudformation` component source based on its `source` configuration. This downloads the component from the specified URI and places it in the appropriate component directory.
</Intro>

## Usage

```shell
atmos aws cloudformation source pull <component> --stack <stack> [flags]
```

## Examples

### Basic Usage

Vendor a component source for a specific stack:

```shell
atmos aws cloudformation source pull vpc --stack dev
```

### Force Re-vendor

Re-vendor even if the component directory already exists:

```shell
atmos aws cloudformation source pull vpc --stack dev --force
```

### With Identity Override

Use a specific identity for authentication:

```shell
atmos aws cloudformation source pull vpc --stack dev --identity admin
```

### Preview with `--dry-run`

Use `--dry-run` to check the component, source configuration, and destination without downloading:

```shell
atmos aws cloudformation source pull vpc --stack dev --dry-run
```

## Arguments

<dl>
  <dt>`component`</dt>
  <dd>**Required.** The name of the Atmos component to vendor.</dd>
</dl>

## Flags

<dl>
  <dt>`--stack` / `-s`</dt>
  <dd>**Required.** The Atmos stack name. Can also be set via `ATMOS_STACK` environment variable.</dd>

  <dt>`--force` / `-f`</dt>
  <dd>Force re-vendor even if the component directory already exists. Without this flag, the command skips vendoring if the directory exists.</dd>

  <dt>`--identity` / `-i`</dt>
  <dd>Identity to use for authentication when downloading from protected sources. Overrides the component's default identity.</dd>
  <dt>`--dry-run`</dt>
  <dd>Validate static configuration and show the destination without authentication,
  downloads, or deletion.</dd>
</dl>

## Description

The command downloads the configured source, applies path filters, and copies
the result to the component's resolved directory. Existing downloads are skipped
unless `--force` is set.

The destination follows the base component, `working_directory`, and workdir
settings. See [Component Directories](/stacks/components/aws-cloudformation#component-directories).

## Configuration

The component must have `source` configured in its stack manifest:

```yaml
components:
  "aws/cloudformation":
    vpc:
      source:
        uri: github.com/cloudposse/cloudformation-aws-components//modules/vpc
        version: 1.0.0
        included_paths:
          - "*.yaml"
        excluded_paths:
          - "*.md"
          - "tests/**"
```

## Output

On success:
```text
Vendoring component 'vpc' from source...
Downloading from github.com/cloudposse/cloudformation-aws-components//modules/vpc?ref=1.0.0
✓ Successfully vendored component to components/cloudformation/vpc
```
