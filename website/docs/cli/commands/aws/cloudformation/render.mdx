<Intro>
  Render the component's inline `template:` or file-based `path:` template,
  provisioning `source:` and generating configured files first when enabled. Local
  or already-provisioned sources can render offline without AWS credentials when
  their configuration does not require remote lookups. A cold remote `source:` must
  be fetched first; private S3 sources use the component’s resolved AWS identity.
</Intro>

## Usage

```shell
atmos aws cloudformation render <component> --stack <stack> [options]
```

```shell
atmos aws cloudformation render vpc -s plat-ue2-dev
```

Render all or affected components in dependency order:

```shell
atmos aws cloudformation render --all -s plat-ue2-dev
atmos aws cloudformation render --affected --base origin/main
```

Render components filtered by tags or labels (composes with `--all`/`--affected` to narrow the selected set further):

```shell
atmos aws cloudformation render --all --tags production,tier-1
atmos aws cloudformation render --affected --labels cost-center=platform
```

:::note
`render` does not deploy or validate a stack through the CloudFormation API.
Source provisioning and configured secret or output lookups can still require
authentication and network access. To preview the changes an `apply` would
actually make against the deployed stack, use
[`diff`](/cli/commands/aws/cloudformation/diff) (alias [`plan`](/cli/commands/aws/cloudformation/plan)).
:::

When [`auto_generate_files`](/cli/configuration/components/aws-cloudformation) is enabled,
`render` writes the component's [`generate`](/stacks/components/aws-cloudformation#generated-files)
files into its isolated workdir before loading `path`. `--dry-run` skips generation.
