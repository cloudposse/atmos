## Usage

```shell
atmos aws cloudformation backend list <component> --stack <stack> [options]
```

## Examples

```shell
atmos aws cloudformation backend list vpc -s plat-ue2-dev
atmos aws cloudformation backend list vpc -s plat-ue2-dev --format json
```

## Behavior

The command lists every S3 target for one component; it does not accept
`--target`. Supply a component name and `--stack`.

The `table` format prints a header row (`TARGET`, `BUCKET`, `REGION`,
`STATUS`). The `json` and `yaml` formats use snake_case keys; see [`backend
describe`](/cli/commands/aws/cloudformation/backend/describe) for the shape.

### Targets that cannot be inspected

Each target uses its own identity. Failed authentication or bucket checks appear
as error rows; healthy targets still appear in the output:

```text
TARGET               BUCKET                         REGION         STATUS
a-broken             broken-bucket                  us-east-1      error: aws/cloudformation component requested an identity, but the auth manager could not resolve it: identity "devv" not found
b-good               good-bucket                    us-east-1      exists
```

In the `json` and `yaml` formats the failed entry carries an `error` field with
the same cause; healthy entries omit it.

After the rows print, the command exits non-zero if any target failed. The
error names the failed targets and their count, and hints to run
`atmos aws cloudformation backend describe --target <name>` for details.
