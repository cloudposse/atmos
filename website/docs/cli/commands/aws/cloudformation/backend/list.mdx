<Intro>
  List every `kind: aws/s3` provision target declared on the component, and
  whether each one's bucket currently exists.
</Intro>

<Experimental />

<CastPlayer title="atmos aws cloudformation backend list --help" src="/casts/screengrabs/atmos-aws-cloudformation-backend-list--help.cast" static chrome />

## Usage

```shell
atmos aws cloudformation backend list <component> --stack <stack> [options]
```

```shell
atmos aws cloudformation backend list vpc -s plat-ue2-dev
atmos aws cloudformation backend list vpc -s plat-ue2-dev --format json
```

## Flags

<dl>
  <dt>`--stack`, `-s` <em>(required)</em></dt>
  <dd>Atmos stack.</dd>

  <dt>`--format`, `-f` <em>(optional)</em></dt>
  <dd>Output format: `table` (default), `yaml`, or `json`.</dd>

  <dt>`--identity`, `-i` <em>(optional)</em></dt>
  <dd>Atmos identity to authenticate with.</dd>
</dl>

The component argument is required. Running `backend list` with only a stack
fails with a hint that shows the full form,
`atmos aws cloudformation backend list <component> -s <stack>`. There is no
stack-wide form (see Behavior below).

## Behavior

Unlike [`atmos terraform
backend`](/cli/commands/terraform/terraform-backend)'s own `list` verb (which
lists every backend across a whole stack, with no component argument),
`backend list` is scoped
to one component: CloudFormation's provision-target model declares `kind:
aws/s3` targets per-component under `provision.targets`, not once per stack,
so there is no component-independent, stack-wide backend inventory to list.
`backend list` never needs `--target` — it always shows every declared target
at once.

The `table` format prints a header row (`TARGET`, `BUCKET`, `REGION`,
`STATUS`). The `json` and `yaml` formats use snake_case keys; see [`backend
describe`](/cli/commands/aws/cloudformation/backend/describe) for the shape.

### Targets that cannot be inspected

Each target authenticates with its own credentials, so one broken target (for
example a mistyped `auth.identity`) never hides the others. `backend list` renders
every declared target. A target whose authentication or bucket check fails
appears as an error row that names the target and the cause, and the healthy
targets print as usual:

```text
TARGET               BUCKET                         REGION         STATUS
a-broken             broken-bucket                  us-east-1      error: aws/cloudformation component requested an identity, but the auth manager could not resolve it: identity "devv" not found
b-good               good-bucket                    us-east-1      exists
```

In the `json` and `yaml` formats the failed entry carries an `error` field with
the same cause; healthy entries omit it.

After the rows print, the command exits non-zero if any target failed. The
error names the failed targets and their count, and hints to run
`atmos aws cloudformation backend describe --target <name>` for details.
