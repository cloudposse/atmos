<Intro>
Create or update a CloudFormation stack without an interactive confirmation.
This is an alias for [`apply`](/cli/commands/aws/cloudformation/apply) with
`--auto-approve` enabled by default.
</Intro>

## Usage

```shell
atmos aws cloudformation deploy <component> --stack <stack> [options]
```

## Examples

```shell
atmos aws cloudformation deploy vpc -s plat-ue2-dev

# Deploy components filtered by tags or labels (composes with --all/--affected)
atmos aws cloudformation deploy --all --tags production,tier-1
atmos aws cloudformation deploy --affected --labels cost-center=platform
```

## Arguments

<dl>
  <dt>`component` <em>(required unless selecting multiple components)</em></dt>
  <dd>CloudFormation component name in the Atmos stack.</dd>
</dl>

## Flags

<dl>
  <dt>`--stack`, `-s` <em>(required for a single component)</em></dt>
  <dd>Atmos stack. With bulk selection flags, limits the selected components to this stack.</dd>

  <dt>`--target` <em>(optional)</em></dt>
  <dd>Provision target to deliver to. Defaults to `provision.default`, otherwise the implicit direct-deploy target.</dd>

  <dt>`--auto-approve` <em>(optional, defaults to `true`)</em></dt>
  <dd>Skip the interactive confirmation prompt. Pass `--auto-approve=false` to require confirmation, just like `apply` without the flag.</dd>

## Behavior

`deploy` runs exactly like [`apply`](/cli/commands/aws/cloudformation/apply#how-apply-runs)
with the confirmation turned off: it creates the changeset, prints the predicted
changes on stderr, and executes the changeset without asking. A changeset that
would change nothing is deleted, `deploy` prints `No changes`, and the follow-up
steps still run. With `--auto-approve=false` it asks after showing the changes,
like `apply`.
