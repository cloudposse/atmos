  <dt>`--all` <em>(optional)</em></dt>
  <dd>Process all `aws/cloudformation` components. Deployment runs dependencies first; deletion runs consumers first.</dd>

  <dt>`--affected` <em>(optional)</em></dt>
  <dd>Process affected `aws/cloudformation` components and their dependencies. Compares the working tree against a base: see `--base` and the Git flags below.</dd>

  <dt>`--include-dependents` <em>(optional)</em></dt>
  <dd>With `--affected`, include dependent `aws/cloudformation` components.</dd>

  <dt>`--base` <em>(optional)</em></dt>
  <dd>Git base ref or SHA to compare against for affected detection: `--base=origin/main`. A value that looks like a commit SHA is treated as `--sha`, anything else as `--ref`. Used with `--affected`.</dd>

  <dt>`--tags` <em>(optional)</em></dt>
  <dd>Filter by tags (comma-separated, matches any): `--tags=production,tier-1`. Composes with `--all`/`--affected` to narrow the selected set further; cannot be combined with a single component argument.</dd>

  <dt>`--labels` <em>(optional)</em></dt>
  <dd>Filter by labels (repeatable and/or comma-separated `key=value` or `key:value` pairs, matches all): `--labels=cost-center=platform,compliance=sox`. Composes with `--all`/`--affected`/`--tags`; cannot be combined with a single component argument.</dd>

  <dt>`--ci` <em>(optional)</em></dt>
  <dd>Enable [CI integration](/ci#outputs) for supported operations when `ci.enabled` is configured. Summary and output-variable publishing use their respective CI settings. Also enabled by `CI` and `ATMOS_CI`.</dd>
