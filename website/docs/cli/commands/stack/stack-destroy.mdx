<Intro>
Destroy selected components that remain defined in the current stack configuration.
Consumers run before their prerequisites, using each component type's registered destroy handler.
</Intro>

<CastPlayer title="atmos stack destroy --help" src="/casts/screengrabs/atmos-stack-destroy--help.cast" static chrome />

## Usage

```shell
atmos stack destroy --all --stack=dev --dry-run
atmos stack destroy --affected --base=origin/main --stack=dev
atmos stack destroy --all --stack=dev --max-concurrency=2 --auto-approve
```

Use exactly one of `--all` and `--affected`. Positional component arguments are
rejected; to destroy one component, run `atmos <kind> destroy <component> --stack=<stack>`.
A `--stack` value that names no existing stack is an error. Selection, dependency
expansion, concurrency, logging, and dry-run behavior match
[`stack deploy`](/cli/commands/stack/stack-deploy). Execution runs in reverse
dependency order, so consumers are destroyed before the prerequisites they use.
Expansion flags retain their normal graph meaning even though execution reverses the
selected edges. Prerequisites and consumers are not automatically added to the
selection.

## Supported component kinds

- Terraform runs `atmos terraform destroy`.
- Helmfile runs `atmos helmfile destroy`.
- Helm runs `atmos helm destroy`, an alias of `atmos helm delete`.
- Kubernetes runs `atmos kubernetes destroy`, an alias of `atmos kubernetes delete`.
- AWS CloudFormation runs `atmos aws cloudformation destroy`, an alias of
  `atmos aws cloudformation delete`.
- Custom component kinds are supported when a custom command named `destroy` declares
  `component.type`. The `--all` flag and dependency expansion select these
  components; `--affected` does not select custom kinds yet.

Packer and other kinds without a `destroy` handler are excluded with a notice.

## Checks before execution

Atmos builds the full plan before it starts any component:

- Components with `metadata.locked` are excluded with a notice.
- The command fails when a component outside the selection still requires a
  component that would be destroyed. The error lists each `consumer -> target` pair.
  Add `--include-dependents` to destroy the consumers first, or widen `--stack` to
  cover them. Optional dependencies do not block a destroy.
- Dependency cycles are reported as readable paths, such as
  `terraform/dev/a -> terraform/dev/b -> terraform/dev/a`.

## Approval

Each component command owns its approval behavior. One worker preserves stdin and
live output for interactive prompts. The `--auto-approve` flag appends the approval
arguments that each handler registers:

- Terraform destroy and CloudFormation destroy prompt for confirmation, so
  `--auto-approve` passes `-auto-approve` and `--auto-approve` to them respectively.
- Helm, Kubernetes, and Helmfile deletes do not prompt, so `--auto-approve` adds
  nothing for them.
- Custom commands receive no approval arguments.

Concurrent workers have no stdin. With `--max-concurrency` above `1`, a plan that
contains a component that would prompt is rejected before anything runs, unless
`--auto-approve` is set or the command is a `--dry-run`.

## Output

Each excluded component produces a notice with its kind, stack, component, and the
reason. During execution, every component reports a success, failure, or skipped
line. The command finishes with a tally:

```text
3 succeeded, 0 failed, 0 skipped, 1 excluded
```

With `fail-fast`, components still pending after a failure are skipped. With
`keep-going`, only the components that wait on the failed one are skipped.

## CI

In CI mode, each component command runs with `ATMOS_CI=true`. Children inherit the rest
of the environment, so provider variables such as `GITHUB_ACTIONS` pass through. The
`--ci` flag sets `ATMOS_CI` for the children without forwarding the flag itself, because
not every component command accepts it. Job summaries and outputs also require
`ci.enabled: true` in `atmos.yaml`.

Concurrent components would otherwise append to the same job summary and overwrite
the same output keys. Atmos gives each component private summary and output files and,
when the run finishes, writes:

- One job summary: a table of component, kind, stack, and result with the tally,
  followed by each component's own summary in a collapsible block, so per-component
  detail is preserved.
- One set of outputs, listed below.

<dl>
  <dt>`components_total`</dt>
  <dd>Number of components in the plan, excluding the ones reported as excluded.</dd>
  <dt>`components_succeeded`</dt>
  <dd>Number of components that succeeded.</dd>
  <dt>`components_failed`</dt>
  <dd>Number of components that failed.</dd>
  <dt>`components_skipped`</dt>
  <dd>Number of components skipped because of an earlier failure.</dd>
  <dt>`components_excluded`</dt>
  <dd>Number of components excluded from the plan with a notice.</dd>
  <dt>`success`</dt>
  <dd>`true` when no component failed.</dd>
  <dt>`results`</dt>
  <dd>Compact JSON array with one entry per component: `kind`, `stack`, `component`, `status`, and `outputs`, the key-value outputs that component's command produced. The per-component `summary` output is omitted because the job summary already shows it.</dd>
</dl>

```shell
atmos stack destroy --all --stack=dev --ci --max-concurrency=2
```

Workflow commands such as `::add-mask::`, `::group::`, `::error::`, `::warning::`, and
`::notice::` stay intact with `--max-concurrency` greater than `1`. Atmos writes these
lines without the component prefix, because CI providers only recognize them at the
start of a line.

Each component command groups its own output, and with `ci.groups.mode: invocation`
each component gets exactly one group. The `stack destroy` command itself opens no
group, because providers do not nest groups.

## Hooks

Helm, Kubernetes, and CloudFormation expose `destroy` aliases for their existing
`delete` operations. The preview shows the actual hook events those commands fire;
for these aliases, hook events retain the `delete` name. Helmfile destroy fires
`before.helmfile.destroy` and `after.helmfile.destroy`. Single-component Terraform
destroy currently does not fire user lifecycle hooks, so none are promised in its
preview.

## Flags

<dl>
  <dt>`--all`</dt>
  <dd>Select every component that defines a `destroy` operation. Exactly one of `--all` or `--affected` is required. Default: `false`.</dd>
  <dt>`--affected`</dt>
  <dd>Select components affected by the Git comparison. Exactly one of `--all` or `--affected` is required. Default: `false`.</dd>
  <dt>`--stack`, `-s`</dt>
  <dd>Intersect the initial selection with a canonical stack name. A name that matches no stack is an error. Environment variable: `ATMOS_STACK`. Default: All stacks.</dd>
  <dt>`--base`</dt>
  <dd>Base Git ref or SHA for the comparison. Atmos detects it automatically in supported CI environments. Requires `--affected`. Default: Existing affected baseline rules.</dd>
  <dt>`--ref`</dt>
  <dd>Git reference to compare against. Requires `--affected`.</dd>
  <dt>`--sha`</dt>
  <dd>Git SHA to compare against. Requires `--affected`.</dd>
  <dt>`--repo-path`</dt>
  <dd>Existing repository to use as the comparison baseline. Requires `--affected`; cannot be combined with `--base`, `--ref`, `--sha`, `--ssh-key`, `--ssh-key-password`, or `--clone-target-ref`.</dd>
  <dt>`--ssh-key`</dt>
  <dd>SSH key for cloning the comparison baseline. Requires `--affected`.</dd>
  <dt>`--ssh-key-password`</dt>
  <dd>Password for the SSH key. Requires `--affected`.</dd>
  <dt>`--clone-target-ref`</dt>
  <dd>Clone the comparison baseline. Requires `--affected`. Default: `false`.</dd>
  <dt>`--include-dependencies[=N]`</dt>
  <dd>Include prerequisites of the selected components. The bare flag expands without a depth limit; use the `=N` form, such as `--include-dependencies=2`, to limit the depth. Default: Disabled.</dd>
  <dt>`--include-dependents[=N]`</dt>
  <dd>Include consumers of the selected components. The bare flag expands without a depth limit; use the `=N` form to limit the depth. Default: Disabled.</dd>
  <dt>`--max-concurrency`</dt>
  <dd>Maximum number of active component operations. One worker permits interactive prompts. Default: `1`.</dd>
  <dt>`--failure-mode`</dt>
  <dd>`fail-fast` stops at the first failure. `keep-going` finishes independent branches while dependents of failures are skipped. Default: `fail-fast`.</dd>
  <dt>`--log-order`</dt>
  <dd>`stream` prints component output as it arrives. `grouped` emits complete component logs in stable dependency order and applies when `--max-concurrency` is greater than `1`. Grouped mode sends each component's stdout to stdout and its headers and stderr to stderr. Default: `stream`.</dd>
  <dt>`--dry-run`</dt>
  <dd>Preview selection, commands, relationships, and lifecycle hooks without destroying anything. Environment variable: `ATMOS_DRY_RUN`. Default: `false`.</dd>
  <dt>`--identity`, `-i`</dt>
  <dd>Forward the identity to each child. Use `--identity` without a value to select interactively, which requires `--max-concurrency=1`. Environment variable: `ATMOS_IDENTITY`. Default: Component command behavior.</dd>
  <dt>`--auto-approve`</dt>
  <dd>Append each handler's registered approval arguments. Terraform destroy and CloudFormation destroy prompt without it; Helm, Kubernetes, and Helmfile deletes do not prompt. Default: `false`.</dd>
  <dt>`--ci`</dt>
  <dd>Run in CI mode. Every child component command runs with `ATMOS_CI=true`, and Atmos publishes one combined job summary and one set of outputs for the whole run. Without the flag, CI mode turns on when `ATMOS_CI` or `CI` is truthy or a CI provider is detected; an explicit `--ci=false` turns it off. Environment variables: `ATMOS_CI`, `CI`. Default: `false`.</dd>
  <dt>`--skip-hooks[=names]`</dt>
  <dd>Skip all hooks, or the comma-separated hook names; previews identify skipped hooks. Environment variable: `ATMOS_SKIP_HOOKS`.</dd>
</dl>

Comparison flags (`--base`, `--ref`, `--sha`, `--repo-path`, `--ssh-key`,
`--ssh-key-password`, and `--clone-target-ref`) require `--affected` and are rejected
otherwise. Only the environment variables listed above apply to this command. Variables
that other commands bind to similar settings, such as `ATMOS_TERRAFORM_DESTROY_ALL`, do
not change the selection.

## Scope

This command does not recover removed definitions. Deleted affected components are
reported and omitted. It does not remove stack manifests; use `stack config delete`
for configuration values. Manifest deletion under `stack delete` is reserved for a
future breaking release.
