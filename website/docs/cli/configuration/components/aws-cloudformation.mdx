<Intro>
  Tell Atmos where native `aws/cloudformation` component files live. This
  project-wide setting keeps stack files focused on what to deploy, while
  `atmos.yaml` defines where CloudFormation components are found. Stacks are
  deployed directly through the AWS SDK for Go v2, so no `aws` CLI or
  `cfn`/`sam`/`Rain` binary is required.
</Intro>

<Experimental />

## Configuration

<File title="atmos.yaml">
```yaml
components:
  "aws/cloudformation":
    # Base path to native aws/cloudformation component directories (where local
    # templates live). Defaults to components/cloudformation.
    base_path: components/cloudformation

    # Generate component files before operations that read the local template.
    auto_generate_files: false
```
</File>

Quoting the `aws/cloudformation` key is optional in YAML (a `/` doesn't require it) — quoted here
to match the convention used throughout these docs and examples.

## Configuration Reference

<dl>
  <dt>`base_path`</dt>
  <dd>
    Base directory for native `aws/cloudformation` components. A component's
    `path:` (and, when set, `stack_policy.file:`) resolve relative to its
    component directory under this base path. Defaults to
    <code>components/cloudformation</code>.
  </dd>
  <dt>`auto_generate_files`</dt>
  <dd>
    When `true`, writes the component's [`generate`](/stacks/generate) block
    before operations that consume its local template or stack policy. Defaults
    to `false`. A nonempty block automatically uses an isolated workdir for each
    stack/component instance; explicitly setting `provision.workdir.enabled: false`
    is an error. See [generated files](/stacks/components/aws-cloudformation#generated-files)
    for operation coverage and examples.
  </dd>
</dl>

Component-level fields — `template`, `stack_name`, `parameters`, `capabilities`,
`tags`, `stack_policy`, `role_arn`, `notification_arns`, `disable_rollback`,
`termination_protection`, `timeout_in_minutes`, `source`, `provision`, `generate`, `auth`,
and `dependencies` — are configured per stack, not in `atmos.yaml`. See
[CloudFormation stack configuration](/stacks/components/aws-cloudformation).

## Region Resolution

CloudFormation API calls need an AWS region. Atmos resolves it in this order,
most specific wins:

1. `settings.aws_cloudformation.region` on the component
2. The active identity's region
3. The AWS SDK's default credential/region chain (`AWS_REGION`, shared config)

```yaml
components:
  "aws/cloudformation":
    vpc:
      settings:
        aws_cloudformation:
          region: us-west-2
      # ...
```

A component `env` entry such as `AWS_REGION` or `AWS_DEFAULT_REGION` does not
select the region, because Atmos builds the CloudFormation client in-process
from the list above and never reads the component `env` for it. When the
component `env` sets one of them to a different region than the one Atmos
resolved, Atmos prints a warning that the value is ignored. Set
`settings.aws_cloudformation.region` to override the region.

The account is the active identity's account. A [delivery target's auth block](/stacks/components/aws-cloudformation#target-authentication)
can select a different identity for that destination; an explicit CLI identity
still takes precedence.

See the [`atmos aws cloudformation`](/cli/commands/aws/cloudformation)
command reference and the
[CloudFormation stack configuration](/stacks/components/aws-cloudformation) for
component-level fields.
